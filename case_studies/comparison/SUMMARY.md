# Comparison summary: Lean 4, Idris 2, Rust, the Racket family and LRL

Generated by `python3 case_studies/comparison/make_summary.py` from the three results files
(`results_lean_idris.md`, `results_rust_racket.md`, `results_lrl.md`); do not edit by hand.
Each cell is derived only from the rows of those files for that property and language:

- *static (compile error), n of n violations*: every negative program (a violation of the property) was
  rejected before running; n is the number of negative programs, which differs between languages;
- *run time only*: violations were caught only when the program ran;
- *not detected*: a violation compiled and ran; *static k, run time j, not detected m of n violations*
  gives the counts when the negative programs had different outcomes;
- *not expressible*: no correct (positive) program using the feature was accepted, or (LRL) an evidence row
  shows that the feature does not exist (no in-place update; no operation on references);
- *k of n correct programs not accepted*: some, but not all, positive programs were rejected (or failed);
- *checks pass, code generation fails*: LRL's checks accepted the positive program but rustc rejected the
  generated Rust (a code-generator limitation);
- *limit probe*: programs that probe whether the tool can express or enforce the property at all
  ("limit" rows of the results files), with their observed outcome;
- the files in parentheses are the positive programs (or the probes / negatives when there is no positive one);
  *code excerpts* point to the rows of the results files that quote the compiler's intermediate or generated
  code for the property (e.g. whether an update is done in place, or whether a proof is passed at run time);
  a negative row with a bracketed build variant (Rust Q1 `[--emit=metadata]`, a check-only build) is not an
  excerpt: it is counted among the violations.

Racket family dialects: Racket = `#lang racket/base`; Typed Racket; Typed Racket + refinements;
Cur (dependent types via Turnstile+ macros); Turnstile lin (the linear-types example language).
LRL dialects: the typed and the dynamic code generator (both run the same checks).
