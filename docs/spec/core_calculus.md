# Core Calculus Specification

## 1. Kernel Calculus Base

The kernel is based on the **Calculus of Inductive Constructions (CIC)** dependent type theory, closely aligned with Lean's kernel.

## 2. Universes

*   **`Prop` (Sort 0)**: The universe of computationally irrelevant propositions.
    *   **Impredicative**: `Prop` is impredicative. The universe level of a Pi-type `Π (x : A), B` is `Prop` if `B : Prop`, regardless of the universe of `A`.
    *   **Erasure**: Terms in `Prop` are proofs and are erased at runtime.
*   **`Type u` (Sort u+1)**: A hierarchy of computational types, indexed by universe levels `u`. It is not cumulative: a type in `Sort u` is not accepted where a type in a larger sort is expected.
    *   **Predicative**: The universe level of `Π (x : A), B` where `B : Type v` is `max(level(A), v)`.
*   **Binder types are types**: in `Π (x : A), B` both `A` and `B` must be types (their types reduce to a sort), and the binder type of `λ`, `let` and `fix` must be a type; the kernel reports `K0004` (`ExpectedSort`) otherwise (an opaque alias of a sort counts as a sort).

## 3. Function Kinds (Ownership)

`Pi` and `Lam` carry a function-kind annotation (`Fn`, `FnMut`, `FnOnce`) that
controls ownership and call semantics for runtime values. The kind is part of
type identity (no definitional equality across kinds). Beta reduction is
unchanged. See `docs/spec/function_kinds.md` for the full specification.

Core grammar excerpt:

```
FnKind ::= Fn | FnMut | FnOnce
Pi(ty, body, binder_info, fn_kind)
Lam(ty, body, binder_info, fn_kind)
```

## 4. Inductive Types and Elimination

The kernel supports inductive definitions.

*   **Well-formed declarations**: the arity must be a type `Π (x1 : A1) ... (xn : An), S` whose binders are written out and whose result `S` is a sort, or an alias (e.g. an `opaque` definition) that unfolds to one; every constructor type must be a type, i.e. its binder types are types and its result applies the inductive to arguments of the arity's binder types. Violations are `K0004` (`ExpectedSort`) or a type mismatch. (Without these checks an arity such as an empty proposition, `Bot : False`, made `Bot` itself a closed proof of `False`.) The universe check of constructor fields uses the unfolded result sort when the arity is written through an alias.
*   **Zeta expansion first**: the kernel reads the arity and the constructor types syntactically (parameter inference, strict positivity, nested occurrences, the recursive arguments of the recursor and of ι-reduction, Copy derivation), so it first replaces every `let` in them by its value (zeta reduction, part of definitional equality); the declaration is stored in that form. A let-bound variable therefore cannot hide an occurrence of the inductive, and a field written `(let Y (sort 1) L Y)` in an inductive `L` is a recursive argument with an induction hypothesis.
*   **Strict positivity** (as in Lean 4 and Coq): in a constructor field the inductive being declared may occur only as the head of the field type, or of the codomain of a Pi in it, applied to its own parameters (a field `Nat -> T` of `T` is fine); it must not occur in the domain of a Pi, at any depth. Violations are `K0015` (`NonPositiveOccurrence`). Occurrences as an argument of another type (`List T`) are nested inductives, which are not supported (`K0016`). The inductive also may not occur in the arguments (parameters or indices) of a constructor's **result type** (as in Lean 4 and Coq): `(inductive T (pi P (sort 0) (sort 0)) (ctor base (T (pi x (T Tru) False))))` is rejected with `K0015` (`InductiveInCtorResultArg`).
    *   `(ctor mk (pi f (pi x Bad False) Bad))` is rejected (a negative occurrence gives `omega := λ b. unroll b b` and a closed proof of `False` by `omega (mk omega)`), and so is the same field written `(let X (sort 0) Bad (pi x X False))`.
    *   An occurrence under two arrows, `(ctor intro (pi g (pi p (pi a A (sort 0)) (sort 0)) A))` (`intro : ((A -> Prop) -> Prop) -> A`), is positive but not strictly positive and is rejected: with the impredicative `Prop`, `f P := intro (λ Q. P = Q)` is injective, and the diagonal predicate `W x := ∃ P. f P = x ∧ ¬ P x` gives a closed proof of `False` (Coquand–Paulin).
*   **Failed declarations leave nothing behind**: a declaration rejected by any check, including a failed `copy` derivation (`K0029`), is not registered (not even as an empty type), so its name can be declared again.
*   **Universe rule for constructor fields** (as in Lean 4 and Coq): if the arity ends in `Sort u` with `u` not `Prop`, every constructor **field** `(x : A)` must have a type in a universe at most `u`: `A : Sort v` with `v ≤ u`. The fields are the binders of a constructor type after the inductive's uniform parameters (constructor types repeat the parameters as their leading binders). The level `v` is the sort of the inferred type of `A`, so a field of type `Sort l` has level `l+1` (`Sort l : Sort (l+1)`) and a field of type `Π (x : Nat), Sort 1` has level 2. Violations are `K0017` (`UniverseLevelTooSmall`). Surface programs write only concrete levels (`(sort n)`); for declarations with universe-level parameters (kernel API), `v ≤ u` must hold for every assignment of the parameters (Lean 4's comparison: `u+1 ≤ max u v + 1` holds, `1 ≤ imax 1 u` does not, since `u` may be 0), and level normalisation keeps `imax a u` distinct from `max a u` when `u` may be 0. Level normalisation writes `max (a+1) (b+1)` as `(max a b)+1`; the comparison distributes the successor over `max` again (`(max a b)+k` = `max (a+k) (b+k)`), so that, as in Lean 4, `u+1 ≤ max u v + 2` holds.
    *   Example: `(inductive U (sort 1) (ctor mkU (pi A (sort 1) U)))` is rejected: its field has a type of level 2. Accepting it would let `El : U -> (sort 1)` (by `match`) satisfy `El (mkU A) ≡ A`, i.e. make `(sort 1)` a retract of a type in `(sort 1)`, the setting of Hurkens' paradox for `Type : Type`. Declared in `(sort 2)` it is accepted (a retract of `(sort 1)` in a larger universe is harmless).
    *   Parameters and indices of the arity are **not** constrained (Lean 4 and Coq do not constrain them either): a parameter is not stored in the value and an index is determined by the value's type. `(inductive T (pi A (sort 1) (sort 1)) (ctor mkT (T Nat)))`, a family indexed by a type, lives in `(sort 1)`, and so may an inductive with a parameter `A : (sort 2)` (its fields must still fit: a field of type `A` has level 2 and is rejected in a `(sort 1)` inductive).
    *   Inductive propositions (`u` = `Prop`) are not constrained: a proposition may have a field of type `(sort 1)`; what it may be eliminated into is governed by the elimination restriction below (such a proposition is not large-eliminable).
    *   The universe hierarchy is not cumulative, so the rule also means that a value of a large inductive (e.g. the prelude's `Comp A`, which lives in `(sort 2)` because its constructors store types, see `prelude_api.md`) cannot be stored in, or passed as an argument of, something that expects a `(sort 1)` type.
*   **Large Elimination Restriction**: To maintain proof irrelevance, elimination from an inductive type in `Prop` to a type in `Type u` (where `u > 0`) is restricted. The restriction applies to every inductive that **may** be a proposition: one whose arity ends in a sort whose level is not provably nonzero for every assignment of the level parameters (`Prop`, and with level parameters, kernel API only, `Sort u` or `Sort (imax 1 u)`; not `Sort (u+1)` or `Sort (max 1 u)`). As in Lean 4 this is decided once per declaration, so `PU.{u} : Sort u` with two constructors eliminates only into `Prop`, for every instantiation of `u`.
    *   Allowed only if the inductive type has **zero constructors** (e.g., `False`) or **one constructor** all of whose **fields** are **proofs** (e.g., `True`, `And`). The fields are the constructor's binders after the inductive's uniform parameters; parameters are not restricted (a proposition `Wrap (A : Type)` with one constructor whose only field is a proof may be eliminated into `Type`). A field is a proof if its type is a proposition (the field type's own type is `Prop`). A field whose type is the sort `Prop` itself holds a proposition, not a proof, and blocks large elimination: otherwise `(inductive PW (sort 0) (ctor mkpw (pi P (sort 0) PW)))` would give `up : PW -> Prop` with `up (mkpw P) ≡ P`, making `Prop` a retract of a proposition, which is inconsistent with an impredicative `Prop` (Hurkens' paradox). Violations are `K0027` (`LargeElimination`).
    *   Exception: inductives matching the **equality shape** `(A : Type u) -> (a : A) -> (b : A) -> Prop` with `refl : (A : Type u) -> (a : A) -> Eq A a a` may eliminate into `Type` (transport/J), even though their parameters are in `Type`.
    *   Elimination from `Prop` to `Prop` is always allowed.
*   **Explicit Recursor Universes**: Recursor terms must carry explicit universe levels (e.g., `Rec Nat [u]`). The kernel rejects `Rec` with missing levels. The elaborator computes the level from the motive type and supplies it.
*   **Recursor type (minor premises and indices)**: the recursor's type binds, for each constructor, a minor premise. The minor premise binds the constructor's fields **at their declared types**, each recursive field immediately followed by its induction hypothesis `(ih : C js x)` (the motive at that field's indices and the field), and ends in the motive applied to the constructor's result indices and the constructor applied to its fields. Each type in this telescope — a later field's type, an induction-hypothesis index, a result index — is the constructor's own, read in the interleaved context: a reference to a field keeps its meaning, a reference to anything bound outside the fields is lifted over the induction hypotheses inserted before it. In particular a field whose type depends on an **earlier field placed after a recursive field** keeps that dependency (`node : (r : T) (n : Nat) (v : Tag n) -> T` gives the minor premise `(r : T) (ih : C r) (n : Nat) (v : Tag n) -> C (node r n v)`, with `v : Tag n`, not `Tag ih`). ι-reduction (`try_reduce_rec`) applies the actual fields and the induction hypotheses in the same order, so the recursor type and ι-reduction agree and subject reduction holds. Likewise, in a family whose **index telescope is dependent** (`D : (A : Sort 1) -> (x : A) -> Sort 1`), each index binder in the recursor's main telescope keeps its reference to the earlier indices (`x : A`), not to the motive or a minor premise; the recursor type is well-formed and such a family can be eliminated.
*   **Termination of total definitions** (structural recursion): a recursive call must supply the decreasing argument, and that argument must be structurally smaller than the function's decreasing argument. "Smaller" means a field bound by a minor premise of a recursor **whose major premise is the decreasing argument itself, or is already smaller than it** — not a field of a recursor applied to an unrelated value (`Rec Nat .. (succ n)` does not make its field smaller than `n`), and never the **induction hypothesis** of a minor premise (the IH is the recursor's result on that field, not a subterm of the major premise). A call that stops before the decreasing argument is a partial application that could later be applied to any value and is rejected (`MissingDecreasingArgument`). These rules are enforced for definitions reaching the kernel through either surface syntax or the kernel API; without them a total definition could recurse on its own result and fail to terminate, from which a closed proof of an empty inductive (`False`) follows.

## 5. Definitional Equality and Unfolding

Definitional equality (`a ≡ b`) is decided by a Normalization-by-Evaluation (NbE) engine.

*   **Transparency**: Definitions carry a transparency hint.
    *   **Transparent (Reducible)**: The default. Unfolded during standard type checking.
    *   **Opaque (Irreducible)**: Unfolded only when explicitly requested (e.g., by tactics or specialized reduction modes), effectively abstracting the implementation details.
*   **Reduction**: Includes Beta (λ), Iota (recursion), Zeta (let), and Delta (definition unfolding based on transparency).
*   **Default policy**: Type checking uses transparency mode `Reducible` (respecting `opaque`).
*   **Fuel / budget**: Definitional equality, and the normalisation the type checker uses to expose Pi types and sorts (`whnf`, `whnf_in_ctx`), are fuel-bounded so that the kernel reports that it cannot decide instead of looping. The default fuel is `100_000`, configurable via `LRL_DEFEQ_FUEL` or the CLI flag `--defeq-fuel <N>` (the CLI flag overrides the env var). The fuel is a budget for one check (one conversion problem, or one normalisation: its evaluation and its read-back share the budget), and **every step is charged**: δ (unfolding a definition), ι (a recursor step), β (applying a λ), ζ (a `let`), and every binder that read-back or comparison opens (instantiating a closure with a fresh variable). When fuel is exhausted, the kernel reports `K0048` with context; marking large definitions as `opaque` reduces unfolding pressure. Closure environments are shared during evaluation, so the cost of a step does not grow with the size of the values it handles. Because every step counts, very small budgets no longer suffice for the prelude's own checks.
*   **Depth limit**: independently of the fuel, a fuelled evaluation, read-back or comparison may not nest deeper than `nbe::MAX_EVAL_DEPTH` (`20_000`) steps; deeper nesting reports `K0056` (`NormalizationDepthExceeded`) instead of exhausting the native stack. The limit is sized for the CLI, which runs the compiler on a 1 GiB stack; a client of the kernel API must likewise run the checker on a large stack (on a default 8 MiB thread, a debug build overflows at a few thousand nested steps, e.g. a numeral `succ^2000 zero` in a type).
*   **Fix unfolding**: `fix` (general recursion) is never unfolded during type checking — neither by definitional equality nor by the normalisation that exposes a Pi type for an application (T-App), a sort, or a binder type. Applying a fixpoint there is reported as `K0049` (`DefEqFixUnfold`). A term whose type can only be computed by unfolding a fixpoint (e.g. `zero` at the domain `T zero` of `T := fix T (Nat -> Type) (λ m. Nat)`) is rejected, and a fixpoint application that would never stop unfolding (inside a stuck recursor) is reported instead of exhausting the stack. Use `partial` for general recursion and `opaque` to keep it out of reductions in type checking.
*   **Guarded unfolding of self-referential definitions**: a total definition whose value refers to itself (structural recursion through its own constant: possible through the kernel API, or on the surface when `--allow-redefine` gives a name a new body that calls the old one) is unfolded only when it is applied to its decreasing argument (`rec_arg`, from the termination check) and that argument is a constructor application, as Coq does for `fix`. Otherwise the application stays stuck: unfolding it eagerly gave a stuck call such as `add n zero` an infinite normal form. Definitions that do not refer to themselves (e.g. written with `match`) are unfolded as before.
*   **Safety classification**: Prop classification respects `opaque` by default; explicit contexts can opt in to unfolding for checks like large elimination and Prop-in-data. MIR lowering may still peek through opaque aliases to detect `Ref`/interior mutability. These classification checks do not make `opaque` transparent for definitional equality.

## 6. Axioms and Classical Logic

The kernel supports classical logic via axioms (e.g., Excluded Middle, Choice).

*   **Explicit Tracking**: Axioms must be declared explicitly.
*   **Explicit Classification**: Axioms may carry tags (e.g., `classical`) that the kernel uses to classify dependencies; no name-based heuristics are used.
    *   Surface syntax attaches tags via `(axiom classical name ty)` or `(axiom (classical) name ty)`. Untagged axioms are treated as non-classical.
*   **Dependency Tracking**: Every definition tracks the set of axioms it depends on (transitively). This allows users to know if a theorem relies on classical logic or specific axioms.
*   **`import classical`** introduces the axiom `classical_choice` with type `Π (P : Prop), ((P → False) → False) → P` (double-negation elimination), tagged as classical.

## 7. Completeness & Totality

*   **Total Fragment**: Definitions involved in types must be terminating.
    *   Structural recursion (via `Rec`) or well-founded recursion (via `Acc`) is enforced.
    *   General recursion (`fix`) is **rejected** in total definitions.
*   **Partial Fragment**: General recursion is allowed and cannot participate in definitional equality during type checking. Partial definitions must return an effect type (e.g., `Comp A`), and the kernel enforces this requirement.
    *   `fix` is the only general-recursion form; it is permitted only in `partial` defs. A top-level expression may not contain `fix` either (`C0008`): expressions are evaluated for display, and a looping fixpoint there aborted the process.
    *   **T-Fix**: `fix f : A. t` has type `A` when `A` is a type that reduces to a Pi type and `t : A` in the context extended with `f : A` — with `A` read in that extended context, i.e. weakened by one binder (the kernel and the elaborator used to check `t` against the unweakened `A`, so free variables of the annotation were read one binder off: an ill-typed body was accepted and a well-typed one rejected).
    *   **A fixpoint may not return a proof**: the result type at the end of the fixpoint's Pi telescope must not be a proposition (`K0055`, `FixProofCodomain`). Proofs are erased at run time, so a looping fixpoint returning a proof is never run: `(fix go (pi n Nat (Eq Nat (succ zero) zero)) (lam n Nat (go n)))` stood for a proof of a false equation, and transport along it made compiled code use `true` as a `Nat`.

## 8. Definitions and Redefinition

*   **Values**: only an axiom may be declared without a value (`K0053`, `MissingDefinitionValue`); every other definition is admitted on the strength of its checked value.
*   **Axiom tracking is computed by the kernel**: an axiom always depends on itself, whatever dependency list the client supplies, and its dependents inherit it (`K0023` for a computable definition using it).
*   **Redefinition** (`--allow-redefine`, kernel `Env::set_allow_redefinition(true)`): a name may be given a new definition or declaration only while no other definition or inductive refers to it; otherwise the redefinition is rejected with `K0054` (`RedefinitionWithDependents`, naming the dependents). Every entry is checked against the meaning its references have when it is added, and the kernel does not re-check entries afterwards: replacing a referenced name kept entries that no longer check — with `c := zero`, `p : Eq Nat zero c` proved `Eq Nat zero (succ zero)` after `c := succ zero` (δ uses the current body), and a value of an inductive redeclared without constructors inhabited the empty type; both gave closed proofs of `False` without an axiom. The guard also covers the elaborator's placeholder route (`Env::insert_inductive_placeholder`). A self-referential redefinition is subject to the guarded unfolding of §5.
