were verified, as required by the repository's no-fabrication rule (`CLAUDE.md`). It was written
by Claude (Anthropic) together with the revision. Every command below was run from the repository
root in the revision session; outputs are quoted where they are short.

## 2. Generated figures

All counts, sizes, test totals, timings and tool versions in the paper are macros in
`numbers.tex`, generated by

    python3 paper/jot_r1/scripts/collect_numbers.py --test-log <log of cargo test --all --no-fail-fast>

`numbers_provenance.md` gives the command or source of every macro. The script runs in strict
mode: it refuses to write `numbers.tex` if the artifact paths have uncommitted changes, if the
test log's first line (`revision: <sha>`) names a revision whose code or test inputs differ from
`HEAD`, or if the results contradict statements of the paper (every corpus row and comparison
case matches; no failed or ignored test; the stage-matrix self-check has no inconsistency or
crash; the kernel never rejects a definition that MIR accepts; the only kernel-accepted,
MIR-rejected definitions are borrow errors M200/M203 in negative tests). The final run wrote 130
values and pinned `7d2c91832b2237c6821870803681dac8387a0aba`.

The test log was produced at `4eb6b1d` (`CARGO_TARGET_DIR=... cargo test --all --no-fail-fast`,
exit 0): 73 result lines, 940 passed, 0 failed, 0 ignored. Its revision line, the commands and
every `test result` line are kept in `paper/jot_r1/test_summary.txt`.

## 7. Kernel soundness

The kernel is the paper's logical trusted base. In addition to the corpus, the revision ran a
systematic search for inputs the kernel wrongly accepts (inductive declarations, universes and
elimination, conversion, definitions and axioms, ownership, remaining typing rules). Every
confirmed finding is fixed at `4eb6b1d` with a regression test and is listed in the paper's
"Defects found by the validation" paragraph. Remaining known limitations are stated in the paper
(Section 9) and in `docs/spec/core_calculus.md`; there is no proof of consistency or normalisation
for the kernel's calculus.

## 8. What this audit does not establish

- The correspondence between the rules of Figures 2 and 3 and the Rust code is established by
  reading the code and by tests, not by proof.
- Characterisations of other systems in the related-work section rest on the cited publications
  and, where the paper says so, on the comparison programs in `case_studies/comparison/`.
- The bibliography entries were checked against bibliographic records (Crossref, DataCite, arXiv,
  library catalogues, or publishers' and authors' pages) during the revision; the line
  `%% verified:` above each entry of `bibliography.bib` says how. The compiled paper cites 120 of
  them (`grep -c bibitem` on the generated `main.bbl`).
